# 设备故障数据治理方案

## 一、方案目标

本方案用于统一管理设备结构、故障记录、物料信息和现场记录，保证
数据来源清楚、处理过程可追溯、关联关系有依据、查询结果可复现。

治理后的数据可以支持：

- 设备结构查询；
- 故障现象与设备对象的关联；
- 故障原因与处理方法的整理；
- 物料、耗材和设备部件的对应；
- 故障查询、维修辅助和质量分析；
- 后续数据更新、复核和版本管理。

## 二、治理范围

### 1. 设备结构数据

包括 CAD 模型、设备台账、模块、组件、子组件和设备之间的连接关系。

主要管理内容：

- 设备、模块、组件和子组件的名称与编号；
- 上下级关系和所属模块；
- 设备的型号、类型和来源；
- 组件之间的装配、连接和位置关系；
- 同一设备在不同文件或不同版本中的对应关系。

### 2. 故障与诊断数据

包括故障代码、故障现象、可能原因、处理方法和处理步骤。

主要管理内容：

- 故障代码及其说明；
- 现场描述和标准化故障现象；
- 故障与设备对象的对应关系；
- 故障原因与处理方法的对应关系；
- 维修步骤、顺序、注意事项和预期结果；
- 来源记录、文档位置和审核信息。

### 3. 物料与耗材数据

包括产品零件、螺丝、Tray、批头和其他生产耗材。

主要管理内容：

- 物料编号、名称、规格和版本；
- 物料与设备部件的对应关系；
- 物料与 BOM 的对应关系；
- 物料使用、缺料、更换和寿命信息；
- 物料供应、替代和维修使用信息。

### 4. 工艺与现场记录

包括 NG、抛料、缺料、参数设置异常、连续异常和现场维修记录。

主要管理内容：

- 发生时间、工位、设备和生产阶段；
- 现场现象和影响范围；
- 关联的设备和物料对象；
- 原因判断、处理结果和复发情况；
- 现场记录与正式维修知识之间的对应关系。

## 三、数据来源管理

每个数据来源在进入处理流程前，都建立一条来源登记记录。登记内容包括：

- 来源名称和来源类型；
- 数据负责人和使用负责人；
- 数据版本或快照编号；
- 生成时间和更新时间；
- 文件校验信息；
- 数据敏感性和脱敏状态；
- 原始存放位置和授权范围；
- 允许的使用场景；
- 关联的处理任务和输出文件。

数据来源分为以下几类：

| 来源类型 | 典型内容 | 主要用途 |
|---|---|---|
| CAD 文件 | 设备、模块、组件、子组件 | 建立设备结构 |
| 物料清单 | 零件号、数量、版本 | 核对设备组成 |
| 诊断记录 | 故障代码、现象、原因、处理方法 | 建立诊断知识 |
| 设备台账 | 型号、序列号、工位、负责人 | 补充非 CAD 设备信息 |
| 物料资料 | 规格、寿命、替换和库存 | 建立物料关系 |
| 现场记录 | 报警、维修、NG 和复发情况 | 补充实际使用证据 |

原始文件保持不变。所有清洗、转换、规范化和合并结果都作为新的派生产物保存，
并记录处理时间、处理版本和对应的来源。

## 四、数据标准化规则

### 1. 名称和编号

- 每个对象使用稳定编号作为主要识别方式；
- 名称用于展示，编号用于关联；
- 同义词、缩写、现场叫法和历史名称作为辅助名称保存；
- 同一个对象的不同名称归入同一对象；
- 名称相同但实际对象不同的情况，通过上级设备、位置和来源区分；
- 编号发生变化时，保留新旧编号的对应关系。

### 2. 文本处理

故障文本处理时，保留原始描述，同时生成规范化描述。处理过程包括：

- 统一大小写、空格、下划线和常用分隔符；
- 统一同义词和常见缩写；
- 保留现场原话和标准化表达；
- 记录命中的关键词、来源字段和文本位置；
- 保留所有可能对应的设备或物料对象；
- 对无法唯一确定的结果保留人工审核记录。

程序生成的匹配结果只能作为候选关系，正式关系必须有来源证据和审核记录。

### 3. 设备层级

设备结构统一按照以下层级管理：

```text
设备站点 -> 模块 -> 组件 -> 子组件
```

每个对象必须能够找到自己的上级对象。层级关系需要满足：

- 一个对象有明确的所属上级；
- 上下级关系不出现循环；
- 同一对象不会因为重复导入产生重复编号；
- 每条连接关系的两端都能找到实际对象；
- 结构变化可以追溯到对应的 CAD 或设备资料版本。

## 五、故障与设备的关联规则

### 1. 关联依据

故障与设备建立关系时，优先使用以下依据：

1. 故障代码与设备台账的明确对应；
2. 故障描述中的标准设备名称；
3. 现场记录中的工位、模块和组件信息；
4. CAD 结构中的设备位置和上下级关系；
5. 物料资料中的明确对应关系；
6. 经过人工确认的历史维修记录。

自动匹配、文本相似度和历史关系只能作为辅助依据，不能单独作为最终确认依据。

### 2. 一个故障对应多个对象

一个故障可以同时关联多个对象。例如：

- 缺螺丝可以关联螺丝供料器和螺丝物料；
- 缺 Tray 可以关联 Tray、上料机构和下料机构。

多对象关系需要说明每个对象的作用：

- 主要检查对象：优先检查或更换的对象；
- 辅助定位对象：帮助理解故障位置或系统背景的对象。

不使用未经验证的连续分数代替人工可理解的主次说明。

### 3. 故障原因与处理方法

一条故障记录可以有多个原因，也可以有多个处理方法，但每个原因和处理方法
之间必须有明确对应依据。

管理要求如下：

- 保留原因和处理方法的原始来源；
- 记录原因与处理方法的对应关系；
- 不根据“原因列表”和“处理方法列表”自动自由组合；
- 维修步骤按实际执行顺序保存；
- 保留安全提示、前置条件和预期结果；
- 没有明确依据的关系进入人工审核记录。

## 六、物料清单治理

物料清单与 CAD 结构进行核对时，统一记录以下结果：

- 零件编号和数量都一致；
- 零件编号一致但数量不一致；
- 零件编号需要经过版本或名称转换后才能对应；
- 暂时找不到对应对象；
- 需要人工判断是否为版本变化、命名变化或实际缺失。

每次核对都保存：

- 原始零件编号；
- 标准化零件编号；
- 版本信息；
- BOM 数量；
- CAD 数量；
- 对应对象编号；
- 核对结果和处理说明。

## 七、数据审核机制

数据审核分为四个层次：

### 1. 格式审核

检查文件是否完整、字段是否齐全、编号格式是否正确、数量和日期格式是否统一。

### 2. 结构审核

检查设备层级、物料关系、连接关系和上下级关系是否完整、唯一和可追溯。

### 3. 内容审核

由设备、工艺或维修人员确认故障现象、设备对象、原因和处理方法是否正确。

### 4. 使用审核

确认哪些数据可以用于查询、维修辅助和质量分析，哪些数据只能保留为参考资料。

每条正式数据都保留审核人、审核时间、审核依据和审核结论。

## 八、数据质量检查

每次处理完成后，统一执行以下检查：

- 来源、版本和处理记录是否完整；
- 对象编号是否唯一；
- 名称和编号是否能够相互对应；
- 设备层级是否完整；
- 连接关系两端是否存在；
- 是否出现重复、循环或悬空关系；
- 故障、原因、处理方法和步骤是否能够连贯查询；
- 物料编号、版本和数量是否一致；
- 人工审核记录是否能够追溯；
- 同样的输入能否得到相同的结果；
- 输出文件是否有处理清单和校验信息。

质量检查结果分为：通过、需要复核、暂不使用和排除。每种结果都要保留说明。

## 九、查询和使用规则

查询功能按照固定的查询项目提供，不开放直接修改数据的操作。

基本查询包括：

1. 查询设备、模块和子组件的完整结构；
2. 查询某个组件的直接连接对象；
3. 查询某个站点下的模块和组件；
4. 统计不同类型连接的数量；
5. 查询某个模块的物料组成；
6. 根据故障代码查询故障现象、原因和处理方法；
7. 根据设备对象查询相关故障和维修信息；
8. 查询物料、耗材和处理方法之间的关系。

查询结果需要明确区分：

- 正常返回；
- 没有匹配结果；
- 找到多个可能对象；
- 数据存在但尚未达到使用条件；
- 证据不足，暂不作判断；
- 查询执行失败。

## 十、数据安全和版本管理

- 原始数据只读保存，不在原文件上直接修改；
- 敏感数据先完成脱敏，再进入分析和测试流程；
- 测试集使用合成数据，不复制真实设备日志或未脱敏记录；
- 每次处理生成独立版本和处理清单；
- 每次修改保留修改原因、修改人和修改时间；
- 新版本出现问题时，可以回退到上一版本；
- 数据处理、图谱更新和业务系统使用保持相互隔离。

## 十一、交付内容

本方案配套以下交付物：

1. 数据治理方案；
2. 数据来源和处理要求；
3. 设备、故障、物料和现场记录的管理规则；
4. 数据审核和质量检查规则；
5. 查询和使用规则；
6. [合成测试集](./test_set_v1.jsonl)；
7. [测试集说明](./test_set_v1.md)。

## 十二、方案结论

本方案通过统一数据来源、对象编号、设备层级、故障关联、物料核对、人工审核、
质量检查和版本管理，保证设备故障数据能够持续维护、稳定查询和安全使用。
