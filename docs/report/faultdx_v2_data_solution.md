# 数据治理方案（管理层简版）

## 一句话说明

将分散的诊断、维修、文档、CAD 和物料数据，统一纳入“**可追溯、可审核、可复用、可回退**”的数据治理体系，最终形成可信的数据资产，而不是简单的数据汇总。

## 总体方法

```text
统一登记 → 分类分级 → 清洗标准化 → 关联整合 → 质量审核 → 分级使用 → 持续更新
```

这套方法解决三个核心问题：

- **数据找得到**：知道有哪些数据、在哪里、谁负责；
- **数据看得懂**：统一名称、编码、格式和关联关系；
- **数据用得放心**：有来源、有审核、有权限、有质量证明。

## 不同数据怎么治理

| 数据类型 | 怎么处理 | 怎么治理 | 形成什么能力 |
|---|---|---|---|
| **诊断数据** | 统一故障现象、代码、原因、措施和操作步骤 | 诊断关系必须有来源；原因与措施需明确对应或经专家确认 | 可信诊断知识、结构化查询 |
| **维修与历史案例** | 统一设备、时间、故障、维修动作和结果，识别重复事件 | 先脱敏；历史经验只作为参考，不能自动升级为标准结论 | 相似案例检索、故障趋势分析 |
| **手册与SOP** | 按章节、段落、表格和图片解析，建立全文索引 | 保留文件版本、页码和原文位置；AI提取结果不能覆盖原文 | 技术资料检索、操作指导、证据引用 |
| **CAD与图纸** | 提取图号、版本、装配层级、零部件和几何连接 | 管理图纸版本和知识产权；低置信关系进入人工审核 | 设备结构查询、零部件定位、装配关系分析 |
| **BOM、材料与备件** | 统一料号、名称、规格、单位和数量，建立设备关联 | 校验重复料号、数量异常、替代关系和适用范围 | 物料查询、备件推荐、替代件管理 |
| **设备与零部件主数据** | 建立统一标识、标准名称和别名 | 统一编码；保留合并、拆分、变更和停用记录 | 为所有数据提供统一关联基准 |

## 四项关键技术机制

### 1. 数据血缘（Data Lineage）

每条结果都能追溯到原始文件、具体位置、处理规则和审核记录，回答“这条数据从哪里来、为什么可信”。

### 2. 主数据管理（MDM）

为设备、零部件、故障代码和物料建立统一标识，解决同物异名、同名异物和跨系统编码不一致问题。

### 3. 数据质量门禁（Quality Gate）

数据在正式使用前必须经过完整性、唯一性、一致性、准确性和安全性检查。高风险关系需人工复核，质量不合格的数据不进入正式使用区。

### 4. 版本与回退（Versioning & Rollback）

原始数据保持不变，每次处理形成新版本，并记录输入、规则和变更。新版本出现问题时，可以快速定位影响并恢复到上一版本。

## 数据分层使用

| 数据层级 | 含义 | 使用方式 |
|---|---|---|
| **原始数据** | 未修改的源文件和记录 | 严格授权、只读保存，不直接对外使用 |
| **治理中数据** | 正在清洗、关联或审核的数据 | 仅供内部处理，不作为正式结论 |
| **可信数据资产** | 已脱敏、已审核、质量达标的数据 | 可用于检索、分析和业务应用 |

需要特别强调：**数据完成解析或脱敏，不等于数据已经准确；数据被模型识别，也不等于数据已经成为事实。**

## 管理层看什么指标

建议用五个指标判断治理是否有效：

| 指标 | 管理含义 |
|---|---|
| **来源覆盖率** | 关键数据是否已纳入统一管理 |
| **标准化率** | 设备、故障和物料是否使用统一编码 |
| **质量通过率** | 有多少数据通过完整性、一致性和安全检查 |
| **问题闭环率** | 重复、冲突、缺失和待审核问题是否得到处理 |
| **可追溯率** | 业务结果是否能回到原始来源和审核依据 |

## 最终交付

最终交付不是一个孤立的数据库，而是一套持续运行的数据治理能力，包括：

- 一份完整的数据资产目录；
- 一套统一的数据标准和编码体系；
- 一批按用途分层的可信数据资产；
- 一套数据质量、审核和安全规则；
- 一套来源追溯、版本管理和问题回退机制。

最终效果可以概括为：**底层数据标准化，中间过程可追溯，上层应用可信任，出现问题可回退。**
